    Getting started

    Configuration

    owatch is configured entirely through environment variables — there are no config files and no URL flags:

    Variable What it is
    OWATCH_API_URL Base URL of the Overwatch REST API deployment.
    COGNITO_CLIENT_ID Client ID of the deployment's Cognito user pool app client.
    AWS_REGION Region the Cognito pool lives in (e.g. eu-west-2).
    OWATCH_REFRESH_TOKEN Your Cognito refresh token; exchanged for an access token on every run.

    All four come from the operator of the Overwatch deployment you're using. A missing variable fails fast with an error naming it.

    Developing Overwatch itself?

    A deployed dev stack provides all four: run make login once, then eval "$(make export-envvars)" in your shell.

    The requirements file

    Requirements live in a YAML file: a list of entries, each with a free-form id and the requirement text.

    - id: REQ_001
  requirement: When a user submits a requirement, the Overwatch REST API shall return an assessment.
- id: REQ_002
  requirement: The system should probably be fast.

    IDs must be non-empty and contain only letters, digits, _ or -, so they stay unambiguous in YAML, logs, and error messages.

    Assessing a requirement

    Name the requirement to assess with -r and pass the file:

    owatch assess -r REQ_001 ./requirements.yaml

    On success the CLI prints the name of a time-stamped assessment file it has written to the current directory:

    assessment_20260826_155425_767111.yaml

    which contains the result:

    - id: REQ_001
  ears_assessment: Compliant
  matched_pattern: Event-driven
  rationale: The requirement follows the When <trigger>, the <system> shall <response> shape.

    See Home for what the verdicts and patterns mean, and the CLI reference for every command and flag.

    When it fails

    • OWATCH_API_URL is not set (or any of the other three) — the environment isn't configured; see Configuration.
    • unknown command "./requirements.yaml" — the assess subcommand was omitted: it's owatch assess -r ... <file>, not owatch -r ....
    • authenticating: ... — the refresh token has expired or the Cognito details are wrong; obtain fresh credentials from your operator.
    • A 500 from the API — the failure is server-side (the model call itself, or its configuration); nothing the CLI flags can fix. Report it to your operator.
